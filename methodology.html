方法論

承襲兒少權監督平台（92 wave）+ 兩公約 / CEDAW 平台之共同方法論，並針對 CRPD 特有要求擴充。

四軸 16 PI 框架

每張 PI 卡（Policy Issue）都經過：

  1. 議題立項（主編核可）
  2. 三層文件治理（raw → clean → publish）
  3. frontmatter 結構化（pi_id / axis / status / agencies / crpd_articles 等）
  4. self_qa 自動檢核
  5. 內部 cold read
  6. 軸四另須三方覆核（主編 + DPO + 法律顧問）
  7. 對外發布

雙面 Steelman

軸四（框架爭議）每張 PI 必呈現雙方最強論述：

  • 「強落實派」代表學者 + 機構 + 政策案例（≥ 5 條）
  • 「強保留派」代表學者 + 機構 + 政策案例（≥ 5 條）
  • 本平台立場（折衷、品質融合派、混合派 等）
  • 明確標示哪些主張是國際委員會立場、哪些是學界爭議、哪些是本平台主張

CRPD 平台特有規範

  • 身障用語規範 — 不用「殘障 / 弱智 / 智障 / 精神病」等冒犯詞，採 person-first language
  • 代位發言透明標記 — 非身障當事人撰寫之發言須前置揭露作者身分
  • 好讀版 (Plain Language) — 高優先 PI 提供心智障礙友善版本
  • WCAG 2.1 AA — 全站視覺 / 鍵盤 / 螢幕閱讀器無障礙稽核
  • 身障當事人顧問小組 — 8 障別代表覆核軸四 PI
  • 求助資源並陳 — 涉個案 / 困境敘述須附 113 / 1957 等專線

Wave-based 開發節奏

每個 wave = 1 個明確目標（30-90 分鐘可完成）+ 1 commit + self_qa 通過。

每 5-10 wave 進行一輪獨立 cold read（由非撰寫者 review）+ SESSION_HANDOVER 更新。

軸四 PI 對外前必須通過至少 2 輪 cold read + 三方覆核。
